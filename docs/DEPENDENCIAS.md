# Dependências externas

Regra do Artur (plano, seção 14): **tudo que vem de fora é documentado no mesmo PR que o introduz.** Pacote npm,
imagem Docker, action do GitHub, binário ou CLI baixado, navegador do Playwright, arquivo de dados, serviço externo,
fonte tipográfica.

Uma linha por item, com as 8 colunas: **Item · Tipo · Versão (exata) · Licença · Para quê · Onde é usado · Data · Link.**
O `pnpm docs:check` (roda no `pnpm check` e no CI) falha, listando o que falta, se algum pacote de `dependencies` ou
`devDependencies` de qualquer `package.json` do workspace, imagem do `docker-compose`, `FROM` de Dockerfile ou action de
workflow não tiver linha completa nas tabelas abaixo. A coluna **Tipo** precisa dizer `npm`, `Docker` ou `Action`, e o
**Item** vai entre crases.

As versões exatas de tudo, inclusive das dependências indiretas, estão no `pnpm-lock.yaml`. Aqui entram só os itens que
o repositório declara, mais os binários que a instalação baixa sozinha (seção própria). Data é o dia em que o item entrou ou foi conferido. Conferência de 31/10/2026: versões e licenças dos 43 pacotes npm contra o `node_modules` e o registro do npm; imagens do compose existentes no registro com a tag indicada; SHAs das actions no GitHub; versões dos navegadores no `playwright-core`.

requisição a mais e nenhum arquivo de fonte servido, e o `next build` segue sem falar com o Google. O primeiro teste, com o arquivo
inteiro do latim (17.252 B, sem preload), subiu o LCP da landing de 2,41 s para 2,55 s no Lighthouse (o pedido da fonte entrava na conta
dele) e saiu no mesmo dia. Outra letra no nome da marca pede um subconjunto novo pelo mesmo `text=`.

## Scripts de instalação do pnpm

O pnpm 12 só roda scripts de instalação dos pacotes liberados em `allowBuilds`, no `pnpm-workspace.yaml`.

| Pacote | Decisão | Motivo |
|---|---|---|
| `@prisma/engines` | liberado | Baixa os binários do motor de migrations (`prisma migrate deploy`) |
| `prisma` | liberado | Script de preinstall do CLI |
| `@swc/core` | liberado | Confere o binding nativo do compilador |
| `@scarf/scarf` | bloqueado | Envia telemetria de instalação; o projeto não precisa dele |
| `protobufjs` | bloqueado | Vem pelo `@opentelemetry/sdk-node` (e os exportadores OTLP) da distribuição da Azure. O script só avisa, no stderr, quando o pacote que depende dele usa um esquema de versão fora do dele; a biblioteca não precisa dele para rodar. O pnpm 12 recusa a instalação se o script não for decidido (`ERR_PNPM_IGNORED_BUILDS`) |
| `unrs-resolver` | bloqueado | O binding nativo já vem por pacote opcional; o script só procura alternativa |

## Extensões de pacote do pnpm (`packageExtensions`)

O que o `pnpm-workspace.yaml` acrescenta ao `package.json` de um pacote de terceiros, quando ele usa algo que não declara.

| Pacote | Extensão | Motivo |
|---|---|---|
| `@nestjs/platform-express` | `peerDependencies: { rxjs: ^7.1.0 }` (o mesmo intervalo do `@nestjs/common` e do `@nestjs/core`) | O `multer/multer.utils.js` dele importa o `rxjs` sem declará-lo, e o Node o achava no `node_modules/.pnpm/node_modules`, onde o pnpm iça uma cópia qualquer: o `pnpm add` de 05/11/2026 (o `motion` e o tooltip) içou o `rxjs@6.6.7` do `inquirer` e nenhuma api HTTP subia ("does not provide an export named catchError"). Como par declarado, ele recebe o 7.8.2 da api, pelo link na pasta dele. Sai quando o Nest declarar o `rxjs` |
